# Optional AI Audio Provider

The existing `MusicGenerationEngine.generate` and `regenerate_stem` methods remain the entry points. The default `AUDIO_PROVIDER=procedural` preserves the tested deterministic renderer and never loads model dependencies or contacts a model service.

## Real Provider

`AUDIO_PROVIDER=musicgen_melody` uses Hugging Face Transformers' `MusicgenMelodyForConditionalGeneration` with pretrained `facebook/musicgen-melody` weights. This is a real neural audio model, not the text LLM used by Module 2. It runs locally; it is not an available hosted Hugging Face Inference Provider endpoint.

Official sources:

- https://huggingface.co/docs/transformers/model_doc/musicgen_melody
- https://huggingface.co/facebook/musicgen-melody

**The weights are CC-BY-NC-4.0. This option is research/non-commercial only and does not satisfy commercial-clearance requirements.** An explicit research acknowledgement is required. Do not use it commercially without appropriate rights. The installed model revision and runtime versions are recorded after actual inference; unknown revision information remains null.

## Independent Parts And Limitations

The engine creates its existing deterministic shared composition plan and per-part guides. Each requested instrument is generated by a separate solo-instrument AI inference conditioned on that part's guide, seed, BPM/key and section description. The final mix is built from those returned waveforms. No frequency-band splitting or separation of a single master is used.

This is a defensible independent-generation strategy, **not proof that MusicGen obeys the solo request or exact musical clock**. It can add accompaniment, miss rhythmic/key constraints or produce vocal-like sounds. Melody/chroma guidance is weaker for drums/bass. Exact PCM duration/rate/alignment, independent-file checks, reconstruction, audio validation and existing regeneration rollback remain enforced; those numeric checks do not prove perceptual instrument purity or harmony. Human/model-based evaluation is still required before claiming assessment compliance.

This initial adapter supports **at most 29 seconds** per inference. It explicitly rejects longer requests; it does not tile/repeat short audio and call it long-form AI generation. With explicit fallback enabled, longer jobs use procedural synthesis and say so. Multi-segment coherent generation is not implemented.

## Setup

Use an appropriate Python environment, sufficient RAM/VRAM and model-cache disk space. No large dependencies or weights are installed/downloaded by the default application or tests.

```powershell
python -m pip install -r backend/requirements-ai.txt
$env:AUDIO_PROVIDER = "musicgen_melody"
$env:AUDIO_MODEL_RESEARCH_ACKNOWLEDGED = "true"
$env:AUDIO_MODEL_LOCAL_FILES_ONLY = "false"
$env:AUDIO_MODEL_CACHE_DIR = "E:\model-cache\musicgen"
$env:AUDIO_MODEL_DEVICE = "cuda"
$env:AUDIO_PROVIDER_FALLBACK = "false"
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8001
```

The first explicitly enabled run may download several gigabytes. No model download is attempted unless generation reaches the provider. Leave local-files-only true for offline runs after provisioning the model cache. `AUDIO_MODEL_TOKEN`, when required for model access, must be entered locally through your secret manager/environment; never place credentials in committed files. Public checkpoint access normally does not require a token. `AUDIO_MODEL_REVISION` should be pinned to a known commit for reproducibility. CPU is available but may be too slow for the configured inference budget.

`AUDIO_MODEL_TIMEOUT_SECONDS` is passed to Transformers' generation time budget and checked afterward. It is cooperative and is not a hard process-kill deadline; initial model loading/GPU operations can exceed it. Sampling seeds are isolated using Torch's forked RNG and serialized model access. Bitwise reproduction across GPUs/runtime versions is not guaranteed.

## Failure And Provenance

- Fallback is disabled by default: missing dependencies, inaccessible weights, timeouts, corrupt/short audio and unsupported durations become structured failed jobs.
- `AUDIO_PROVIDER_FALLBACK=true` explicitly permits whole-job procedural fallback on provider/independent-stem failure before artifact publication. Previously generated AI buffers are discarded. The manifest records the requested provider, failure code/message and actual procedural provenance. It never labels this as AI output.
- Downstream validation failures remain failures; validators are not bypassed or softened to claim AI success.
- Single-stem regeneration preserves other stems. For an existing AI stem, its original provider/model must remain configured; its recorded model revision is reused from the loaded model or automatically pinned for loading. Default procedural parents remain procedural when regenerating, even if the application provider has since changed.
- After a fallback during AI-stem regeneration, the manifest may have mixed per-stem sources. `ai_generated` means any AI stem is present; `all_stems_ai_generated` distinguishes an entirely AI-generated stem set. Each stem retains its actual provider/model/version.

## Tests

```powershell
python -m pytest backend/tests/unit/test_audio_providers.py tests/integration/test_audio_provider_pipeline.py -q --basetemp=test_results/provider-UNIQUE-RUN
```

Offline tests use actual procedural rendering or deliberately injected provider failures. They prove configuration, failure handling, reproducibility and pipeline compatibility, not AI audio quality. The real-model test skips safely by default. To explicitly run it after provisioning access/runtime:

```powershell
$env:RUN_REAL_AUDIO_PROVIDER_TEST = "1"
$env:AUDIO_MODEL_RESEARCH_ACKNOWLEDGED = "true"
python -m pytest tests/integration/test_audio_provider_pipeline.py -k real_musicgen -q --basetemp=test_results/provider-live-UNIQUE-RUN
```

When the model loads successfully, inference or audio-validation failures fail this test rather than being relabelled as a skip. No live AI generation is claimed unless that inference actually executes.
